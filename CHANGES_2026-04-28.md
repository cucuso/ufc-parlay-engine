## What changed

### 1. Reverted sequence features (yesterday's failed experiment)

`last_fight_round`, `streak_of_r1_endings`, `last_fight_was_r1_finish`,
`sec_into_round_avg` were added yesterday and regressed winner -1.0pp. Pulled
them from `build_training_data.py:_last_fight_features()` and
`profile_builder.py:compute_sequence_features()`.

### 2. Added R1-chaos interaction features at matchup level

Multiplicative scalars XGBoost can't dilute. Added in
`build_training_data.py` matchup loop:

```python
matchup['r1_chaos_score']         = a_r1 * b_r1
matchup['r1_chaos_score_recent']  = a_r1_5 * b_r1_5
matchup['both_r1_specialists']    = 1.0 if both >= 0.40 else 0.0
matchup['min_r1_ending_rate']     = min(a_r1, b_r1)
matchup['both_grinders_score']    = a_dec * b_dec
matchup['combined_avg_fight_secs'] = (a_avg_sec + b_avg_sec) / 2
matchup['joint_finish_propensity'] = 1.0 - max(a_dec, b_dec)
```

Mirrored at predict time in `ml_model.py:predict()` so live profiles get the
same row construction.

### 3. CRITICAL BUG FIX: `_feature_columns()` was excluding all matchup features

The filter only kept columns starting with `a_/b_/delta_/wc_`. Every
matchup-level feature already in `enriched_fights.csv` (`composite_advantage`,
`signals_aligned_for_a/b`, `experience_gap`, `veteran_vs_newcomer`,
`schedule_gap`, `style_clash`) was being silently excluded from training.

Fix: added `MATCHUP_FEATURES` set in `ml_model.py` listing the explicit
matchup-level columns to include in `_feature_columns()` output.

Impact: `composite_advantage` instantly became the **#1 feature in the winner
model** at 0.055 importance after the fix. The new R1-chaos interactions
also dominated:

- Finish model: `combined_avg_fight_secs` #1, `both_grinders_score` #2,
  `joint_finish_propensity` #3, `min_r1_ending_rate` #7
- ko_vs_sub model: `both_r1_specialists` #3

### 4. `FORCE_KEEP_FEATURES` whitelist for pruning

Probe XGB undervalues multiplicative interactions because individual
components are already informative. Force-keep these in `_prune_features()`
so they survive the top-30 cut.

### 5. Extreme-matchup flags in `gate_picks()`

ML's isotonic calibration squashes tail predictions toward the population
base rate (~28% for R1 finishes). Even when both fighters are 90% R1
specialists, the model says ~44%. Added pattern-based flags as an explicit
override layer the bettor sees independently of ML's calibrated probability.

Three flag types:

| Flag | Trigger |
|---|---|
| 🔥 R1 SPECIALIST | EITHER fighter `r1_ending_rate ≥ 0.70` (single specialist), OR BOTH fighters above 0.45 (mutual R1 chaos) |
| 🐍 SUB SPECIALIST | Either fighter `sub_win_rate ≥ 0.45` |
| 💥 KO SPECIALIST | Either fighter `ko_win_rate ≥ 0.55` |
| ⏳ GRINDER MATCHUP | `dec_product ≥ 0.30` AND `min(a_dec, b_dec) ≥ 0.50` |

Snapshot now stores per-fighter pace data (`pace_a`, `pace_b`) so flags can
fire from saved JSON without re-running the model.
