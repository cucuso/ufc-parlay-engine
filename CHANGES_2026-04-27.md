# Engine Changes — 2026-04-27

Reference card for the model rebuild after UFC Vegas 116 (4/13 winners, 31%).

## What was wrong

1. **Live Elo drift.** `profile_builder.py` was using the full-career cascade Elo
   (includes regional fights, ONE Championship, etc.) but the model was *trained*
   on UFC-only Elo from `enriched_fighters.csv`. Same fighter, two different
   numbers — train/predict distribution mismatch. Worst offenders: Buchecha
   +230, Montague +262, Polastri +258, Marshall +230.

2. **Missing fight-pace features.** `reaches_r2`, `ends_r1`, finish/method models
   only saw cumulative finish rates. A fighter on a 3-of-4 R1 finish-loss skid
   (Dumas) looked identical to a chinny journeyman. No feature for "this guy's
   recent fights end in chaos."

3. **Gates priced wrong.** "Over 1.5 Rounds" / "Over 2.5 Rounds" thresholds were
   based on raw model confidence, not on edge over typical book vig. Surfaced
   plays with no actual betting edge.

## What changed

### 1. Elo override restored — `profile_builder.py:618-637`

When fighter is in training data → override `elo`, `competition_level`,
`avg_opp_elo`, etc. with the training-snapshot values. Debutants fall back to
the cascade. No retrain needed.

### 2. Seven new fight-pace features

Computed causal expanding-window in `build_training_data.py` (added to
`FighterStats._pace_signature_features()`) and mirrored live in
`profile_builder.py` (`compute_pace_signature()`).

| Feature | What it captures |
|---|---|
| `r1_ending_rate` | % of career fights ending in R1 (W or L) — chaos signature |
| `r1_ending_rate_5` | Same, last 5 fights — current trajectory |
| `decision_rate` | % of career fights going to scorecards — grinder signature |
| `avg_fight_seconds` | Mean fight length — fast-starter vs cardio fighter |
| `recent_3_finish_loss_rate` | % of last 3 fights ending in finish loss |
| `recent_5_finish_loss_rate` | Same, broader window |
| `recent_5_r1_loss_rate` | % of last 5 fights ending in R1 finish loss |

Each becomes 3 columns in matchup CSV (`a_*`, `b_*`, `delta_*`) → 21 new
features available to all 6 models post-retrain.

Verification: Dumas now has `r1_ending_rate=0.50, recent_5_r1_loss_rate=0.40`.
McVey has `r1_ending_rate=0.89, avg_fight_seconds=138`. Pre-retrain these were
invisible to the model.

- Winner cascade: `delta_recent_3_finish_loss_rate` #11, `b_recent_5_r1_loss_rate` #12

## Strategy summary

- **Skip**: ML picks below 60% confidence, R1 finish props, ML above 80% (sparse).
- **Core ML**: 65-80% confidence band, with FW haircut to 65% min for featherweights.
- **Primary product**: Goes Distance / Over 2.5 Rounds — the model's strongest
  calibrated edge after retrain.
- **Skip parlays**: model error compounds. Single bets, flat units.

## Over X.5 grading correction (added late session)

`reaches_r2` and `Over 1.5 Rounds` are NOT the same metric. Books grade Over X.5
**time-based at the round halfway point**, not bell-based. Per Action Network's
UFC betting rules:

> "Over 2.5 wins if the fight is still going with 2:29 remaining in the third round."
> "Bets push if the fight ends at exactly 2:30 in the third round."

Empirically across 8,604 fights, model `reaches_r2` overstates book-graded
Over 1.5 by **+7.3pp** (10.2% of fights that reach R2 end in the *first half*
of R2). Fix: multiplicative haircut applied in `gate_picks()`:

```python
OVER_1_5_HAIRCUT = 0.898   # 1 - 0.102
OVER_2_5_HAIRCUT = 0.933   # 1 - 0.067
over_1_5_prob = reaches_r2 * OVER_1_5_HAIRCUT   # use this for gating
over_2_5_prob = reaches_r3 * OVER_2_5_HAIRCUT
```

Threshold raised to `OVER_1_5_ROUNDS_MIN = 0.78` (applied to the haircut-adjusted
prob, not raw `reaches_r2`).

## Rejected experiments — DO NOT re-attempt without new evidence

### Rules-first override hybrid

Hypothesis: identify simple human-readable rules (R1-specialist matchups,
declining vets, lopsided Elo, finish-loss skids) and override ML when they
fire. `rules_engine.py` was built and `backtest_rules.py` showed rules-only
hits 55.9% winner vs ML's 62.4% — and per-rule analysis suggested some rules
(`b_on_finish_skid` 67.6%, `b_declining_vet` 73.7%) beat ML's *aggregate*.

Result: hybrid was -0.3pp vs pure ML on 1,359 held-out fights. The "rules
beat ML" claim was a **subset comparison fallacy** — comparing rule accuracy
on its trigger set to ML's overall accuracy. ML hit 69.6% on the
b_on_finish_skid subset, beating the rule's 67.6%. Where rules and ML
actually disagree (12 fights), ML was right 8/12. See `backtest_hybrid.py`.

**Lesson:** when evaluating a candidate override, always compare the candidate
to the incumbent's accuracy *on the same trigger set*, never to the
incumbent's *aggregate* accuracy.

`rules_engine.py` is kept as an interpretability tool (explain *why* ML picked
a fighter) but not wired into `predict()`. Anyone proposing a hybrid override
again needs to show per-trigger-set lift, not aggregate-comparison lift.
